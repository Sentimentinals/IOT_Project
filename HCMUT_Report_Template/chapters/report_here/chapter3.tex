
\chapter{Task 2 - NeoPixel LED Control Based on Humidity}

This chapter presents the design and implementation of a NeoPixel LED control system based on real-time humidity monitoring. The objective of this task is to provide intuitive visual feedback of environmental moisture conditions using color-coded RGB lighting. By mapping predefined humidity ranges to distinct LED colors, users can quickly interpret indoor environmental quality without relying on numerical readings. The system categorizes humidity conditions into different operational states such as Normal, Warning, and Critical, each represented by a specific color output. Through this approach, the NeoPixel LED serves as both a monitoring indicator and an early warning mechanism, enhancing overall system usability and environmental awareness.

\section{Semaphore Mechanism and Priority}

To ensure thread-safe state management, we utilize FreeRTOS binary semaphores as signaling flags. Each system state (Normal, Warning, Critical, Fire Alert) is represented by a unique binary semaphore.

\subsection{Signaling Mechanism}
The state transition logic follows a "Take-All, Give-One" approach. When the system state changes, the monitoring task first "takes" (clears) all four semaphores to ensure no conflicting signals exist. Immediately after, it "gives" (sets) only the semaphore corresponding to the new active state. This guarantees that at any given moment, exactly one state semaphore is available for consumer tasks to read.

\subsection{Priority Hierarchy}
The determination of which semaphore to set is governed by a strict priority hierarchy. This ensures that critical safety alerts always override minor warnings. The priority levels are defined as follows:

\begin{enumerate}
    \item \textbf{Priority 1 (Highest) - Fire Alert:} Triggered immediately if the flame sensor detects fire. This state overrides all temperature and humidity readings.
    \item \textbf{Priority 2 - Critical:} Triggered if temperature exceeds 40\textdegree C or humidity drops below 30\%.
    \item \textbf{Priority 3 - Warning:} Triggered if conditions are outside the comfortable range (Temp \textless 15\textdegree C or \textgreater 33\textdegree C, Humidity \textless 40\% or \textgreater 80\%).
    \item \textbf{Priority 4 (Lowest) - Normal:} Active only when no other conditions are met (Temp 15--33\textdegree C, Humidity 40--80\%).
\end{enumerate}

The NeoPixel task respects this hierarchy by checking the system state before applying any color logic. If the state is Fire Alert, it ignores the humidity sensor entirely and displays the emergency red signal.

\section{NeoPixel Task Loop}

The NeoPixel task implements a hierarchical priority system where fire alerts override all other conditions. The pseudocode structure demonstrates this layered decision logic:

\begin{verbatim}
FUNCTION getColorByHumidity(humidity):
    IF humidity < 30: RETURN Red(255,0,0)
    ELSE IF humidity < 40: RETURN Orange(255,100,0)
    ELSE IF humidity <= 60: RETURN Green(0,255,0)
    ELSE IF humidity <= 70: RETURN Cyan(0,200,255)
    ELSE: RETURN Purple(150,0,255)
END FUNCTION

TASK neo_blinky():
    Initialize NeoPixel strip on GPIO 45
    Set default brightness to 50
    
    WHILE TRUE:
        Read sensor data from queue
        Read current system state
        
        IF LED disabled (via RPC control):
            Turn off LED
            CONTINUE
        END IF
        
        IF state == FIRE_ALERT OR flame detected:
            Set brightness to 255 (maximum)
            Display solid bright red
        ELSE IF state == WARNING OR CRITICAL:
            Set brightness based on severity (70 or 100)
            Get color from humidity mapping
            Blink color at 300ms intervals
        ELSE (Normal state):
            Set brightness to 50 (power saving)
            Get color from humidity mapping
            Display solid color
        END IF
        
        Delay 50ms
    END WHILE
END TASK
\end{verbatim}

The color selection function checks humidity ranges to pick the right color. We adjust brightness to save power during normal operation (brightness 50) and make alerts more visible (brightness 70 for warnings, 100 for critical). This makes critical states stand out even when using the same color.

The semaphore-based state checking works as follows: the task first checks if the LED is enabled via RPC control by reading from the sensor data queue. If disabled, the LED remains off. Otherwise, it calls \texttt{getSystemState()} to determine the current system state. Based on the state semaphore, the task selects the appropriate behavior: fire alert displays solid bright red at maximum brightness, warning/critical states blink the humidity-based color at 300 ms intervals, and normal state displays a solid color at reduced brightness.
